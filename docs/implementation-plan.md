# KnowledgeOps Agent：临时数据生命周期与清理机制实施计划

2026-10-16 用户确认并启动长期目标。本文为本轮唯一实施入口，实际状态见 progress.md。已交付的[Harness 可靠性计划](implementation-plan-harness-reliability.source.md)原文保留；旧权限/学习计划仍为历史资料。计划不代表已实现。

## 一、目标、参考结论与已确认取舍

补齐应用层的数据归属、保留期限、删除关系、清理失败恢复和数据库设计交付。保留现有 PostgreSQL、Redis、挂载工作目录与 LangGraph 保存器。

DeerFlow删除会话会清理其workspace/uploads/outputs；“保存到项目”通过复制建立独立文档，不受原会话删除影响；文档先进入回收站，永久清理失败时保留可重试记录。本项目借鉴所有权、并发互斥、文件/数据库核对和重试，不照搬整目录删除，不增加文档回收站。
参考：[删除入口](https://github.com/bytedance/deer-flow/blob/main/backend/app/gateway/routers/threads.py)、[删除测试](https://github.com/bytedance/deer-flow/blob/main/backend/tests/test_threads_router.py)、[独立文档复制](https://github.com/bytedance/deer-flow/blob/main/backend/app/gateway/routers/project_documents.py)、[清理服务](https://github.com/bytedance/deer-flow/blob/main/backend/packages/harness/deerflow/projects/trash.py)。规划已读源码/测试，未运行上游测试；固定参考版本及采用方式在开发说明登记。

- 已结束且依赖已解决的根任务，完整详情及原地恢复数据默认保留30天，每日检查、期限可配；恢复执行后重新计算。
- 运行中、暂停、等回答/审批/子任务、操作结果未知的数据不按时间清理。
- 聊天由用户删除，不随运行详情过期。
- 删除聊天不删除上传资料、知识正文及版本、草稿、独立文件产物、长期记忆正文和学习配置。
- 删除聊天同时处理其摘要、检查点、延续快照、历史检索副本，不能从旁路读回。
- 临时性和持久化分别判断：纯执行对象在内存；可重建缓存和队列消息使用Redis；可靠交接/恢复/幂等数据可短期落PG。持久化不等于永久保留。
- 不把run_events整表迁到Redis，不另造事件传输架构；不恢复已退役的项目累计用量。

## 二、数据分类与保留规则

| 类别 | 存储和用途 | 生命周期 |
|---|---|---|
| 活跃执行对象 | 进程内Future、锁、句柄、流式读取器、命令进程、MCP连接 | 消费完或作用域结束释放；跨Run连接沿用空闲策略 |
| 缓存和通知 | Redis队列、事件副本、确定检查点缓存 | 队列按消费确认，缓存按TTL/容量淘汰、源删除主动失效 |
| 交接与恢复控制 | PG投递、消息交接、子通知、审批、模型关联 | 未消费或恢复/幂等仍需要时保护，不能收到一次通知就删除 |
| 完整运行详情 | 事件、模型请求/响应、资源快照、命令/MCP详情 | 根及依赖结束后30天，恢复重新计时 |
| 当前会话记忆 | 最新延续快照、协议字段、可达历史与材料 | 随会话保留，旧Run清理不破坏继续聊天 |
| 内部运行材料 | 工具长输出、压缩前上下文、命令输出 | 无有效引用且所属运行到期才回收 |
| 用户资产 | 原件、正文/版本/草稿、独立文件、记忆、学习配置 | 独立业务生命周期，不随运行/聊天级联 |
| 派生索引 | 知识/历史/记忆检索片段 | 跟随原件/有效版本，删除原件不留检索副本 |
| 受管暂存 | 上传/输出捕获/原子写入暂存 | 无写入者、恢复依赖、引用且超过24小时才回收 |

目录名称不决定所有权。run_artifacts包含内部材料，不等于最终产物；用户自行创建的工作文件不自动GC。来源关系不授予级联删除权。清理后仅保留聊天展示、业务追溯、防重复执行所需简短记录；无业务引用且聊天已删除的记录可进一步移除。

必须形成逐表/关键字段、Redis键、内存对象和受管目录清单，逐项说明拥有者、生产者、消费者、持久化理由、期限、清理条件和恢复依赖，维护于database-design.md。

## 三、增量实现设计

### A. 生命周期协调与资格

应用层统一清理预览、到期扫描、会话删除和失败重试，具体删除委托既有模块。运行增加清理状态/期限/详情可用性/简短结果，会话增加删除状态，材料增加实际保留引用，新增清理作业保存对象/阶段/游标/简短错误，不复制正文；完成作业自身保留30天。

资格由程序确定。锁定根任务组后复查状态、未消费通知、审批、unknown和引用；与领取/恢复/消息写入共享并发边界，预览不替代执行时复查。

### B. 解除对完整日志的隐含依赖

继续聊天需要的最终消息协议信息保存到会话持久层，隐藏推理不进入UI/检索；删除回执后不能猜测。保存运行状态、最终消息定位、交付引用、必要单次用量为简短结果；发布/恢复/权限事实保留在业务记录。

子结果须主任务已消费且无恢复依赖才清理。保留最新会话快照及仍可恢复运行绑定快照，父快照追溯不无限钉住祖先正文。旧记录不能可信转换时保护并说明，不以空字段伪造迁移。

### C. 访问目录与保留引用

快照累积材料ID只表示可访问目录，不自动形成永久保留。有效聊天内部链接、当前笔记、可达历史批次、可恢复运行、草稿及独立资产引用保护正文。创建/引用/快照保存维护关联，旧结构化引用回填，不明引用保守保护并列预览。清理前再核对，防止与新增引用竞争。

旧快照不能读到绑定后材料；历史原文与派生索引分别处理，唯一原文不当缓存丢弃。清理后提供过期标记，权限范围和内容可用性分别处理。

### D. 分阶段清理

候选/保护原因 → 锁定复查 → 标记清理并封闭恢复/写入 → 保存必要结果 → 检查点/回执/受管文件处理 → 关联记录/索引/缓存清理 → 完成或可重试失败。

业务PG、回执库和文件系统没有共同事务，用持久阶段及幂等重试收敛。检查点复用现有PostgresSaver.delete_thread及缓存失效，不手删框架内部表。文件真实路径须在管理边界，共享引用保护；已不存在算完成，其他错误不能假报成功。

封闭后的重复Celery消息、旧审批及旧调用关联不得重启执行或重置预算。分批短事务、可续跑游标，一个失败不拖住全部。复用API后台维护结构，默认每日扫描，删除作业及时续跑，不加容器或调度服务。维护命令默认只预览、显式执行，自动扫描可关闭。

配置涵盖启用、30天期限、扫描间隔、批量、24小时暂存保护期；读取代码/.env/.env.example同步，保留已有值与密钥。

### E. 只删除聊天

新增GET /api/conversations/{id}/deletion-preview返回影响范围、保留项、阻塞原因及版本；DELETE /api/conversations/{id}复查版本/状态，返回202及作业ID；提供状态查询/失败重试。前端确认明确保留资产。

未完成执行、暂停待恢复、待回答/审批及unknown阻止删除，不隐式取消或裁决。接受后隐藏并阻止全部旧会话读写，后台物理清理；隐藏不算完成。删除聊天、交接、摘要、快照、历史检索、恢复数据及完整调用内容；保留原件、正文/版本、草稿、独立文件与其检索下载。

记忆正文及学习配置保留，已删除聊天的原文证据/消息链接/来源副本清理或标记来源删除。学习任务可解除会话关联，保留配置和业务结果，非终态自动推进停止，原链接显示已删除，沿用配置复用入口新建任务。

MCP池有效性检查增加作用域生命周期，删除后拒绝借用并复用close_scope释放连接；正常跨Run会话复用保持。

### F. 清理后的读取

运行详情增加details_available、details_expires_at、resumable。过期后显示简短结果及不可原地恢复原因；事件分页结束、SSE明确关闭、完整导出返回过期，不制造伪完整报告。有效引用材料继续可读，过期材料明确不可用。删除聊天不能经运行/导出/历史/缓存读回。

不新增开发统计或验收报告UI、维护仪表盘、批量聊天删除、文档回收站或完整资产平台。

## 四、依赖、迁移与数据库交付

顺序：数据清单与只读预览 → 会话协议/简短结果/引用及读取状态 → 清理核心 → 聊天删除及UI → 日常维护/迁移演练/交付。各阶段验证业务不变量后推进，不以日期代替设计。

增量迁移只加结构及必要保守回填，不批量删旧数据。业务库、回执库、框架检查点分别沿用自己的迁移责任。旧终态自纳管给予30天，活跃/未知/不能证明的旧记录保护。回填分批可重入，验证预览后启用自动清理。

复用业务库、回执库、完整挂载区共同备份。代码回退不能恢复清理内容，数据恢复用完整备份集；不清理备份/持久卷。

database-design.md交付数据库/schema与迁移职责、分组关系图、全表与关键字段/外键/唯一约束/索引、生产消费者、存储分工、生命周期、跨存储事务/重试、备份恢复，以及现有/新增/保护范围。

architecture沿一次聊天解释产生哪些数据、结束释放什么、30天清理什么、删聊天保留什么；progress集中进度与证据，旧记录不重写。数据库空间维护沿用autovacuum，不以磁盘立即缩小为验收，不自动VACUUM FULL。

## 五、验收与执行边界

在开发容器用隔离PG/Redis、真实保存器/文件、可控时钟、模型替身和协议样例验证，不开展付费效果实验。

| 编号 | 必须证明的结果 |
|---|---|
| L01 | 全表/关键字段、缓存、内存、文件有拥有者、持久理由和清理规则 |
| L02 | 到期前不删，到期后可清理；暂停/待审批/unknown/未消费结果保护 |
| L03 | 清理旧Run后继续聊天，协议、当前记忆、有效历史及引用可用 |
| L04 | 异步资源释放不丢交接，重复投递/清理/旧恢复不重复副作用 |
| L05 | 各跨存储阶段失败可重试，无错误成功，作业不无限累积 |
| L06 | 与恢复/发送/推进/引用/提取并发时结果一致 |
| L07 | 删聊天后原件、知识/版本、独立产物哈希不变，检索下载正常 |
| L08 | 删除内容不能从摘要/历史/请求/事件/导出/缓存读回 |
| L09 | 到期详情无无限分页/SSE重连，学习无坏链接，MCP作用域释放 |
| L10 | 共享引用/用户文件/越界/符号链接不误删，暂存按保护期回收 |
| L11 | 旧库迁移不丢原数据，回填幂等，配置生效，旧任务有宽限 |
| L12 | 文档/命令/配置/逐项证据及限制完整，不以计划或部分测试冒充完成 |

不提交/推送、不启用GitHub CI、不改桌面个人知识库、不公开部署，不新增数据库/服务/无关重构。用户目标授权本轮实现、所需容器、迁移与隔离验证；正常用户资产不用于破坏性验收。保留全部既有未提交工作和原始证据。
