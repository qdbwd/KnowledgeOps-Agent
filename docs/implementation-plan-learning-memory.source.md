# KnowledgeOps Agent：两种学习模式与通用长期记忆增量实施计划

## 一、修订依据、目标与重要变化

本计划面向 `D:\codes\KnowledgeOps Agent`，完整替换此前“两种学习模式与学习配置”计划中的冲突设计。目标是在现有应用上完成：

- **交互学习**：用户决定方向和取舍，Agent 主动梳理框架、解释内容、发现遗漏并适时建议下一步。
- **委托整理**：确认任务范围后，Agent 在读者与审读子 Agent 的配合下持续整理，用户可以随时介入。
- **通用长期记忆**：在现有偏好机制上扩展用户背景、长期目标、协作习惯等信息的提取、维护、检索和上下文注入。
- **学习配置与读者角色**：将相关长期记忆用于学习业务，支持通用配置与任务个性化配置的编辑、导入、复用和回退。

本轮已读取[此前完整计划](exports/2026-10-11-learning-modes-before-memory.source.md)，并核对项目文档、实际调用链和相关测试。上述核对发生于只读规划阶段。2026-10-12用户确认进入实施；本文件为现行唯一增量实施与验收依据。此前已交付的优化计划保留在[历史快照](exports/2026-10-12-pre-learning-optimization.source.md)，其既有功能合同继续保留，冲突设计以本计划为准。当前开发和验证状态见[进展](progress.md)，不能把计划条目当成已实现事实。

## 二、两种模式的产品行为与运行合同

### 1. 会话、学习任务、单次运行分别负责什么

| 对象 | 保存与负责的内容 |
|---|---|
| **会话** | 用户看到的聊天窗口、连续对话历史及会话短期记忆。 |
| **学习任务** | 一个持续目标的范围、框架、配置、知识单元、进展、成果和授权。 |
| **单次运行 Run** | 一次可领取、执行、取消、恢复和计量的 Agent 执行过程。 |

默认建议一个会话围绕一个学习任务，但不强制。用户可以在同一会话完成一个任务后开始另一个，也可以切回旧任务；同一会话同时只自动推进一个学习任务。

具体约定：

- 新学习任务继承正常会话背景，**不建立另一套短期记忆库**。
- 当前任务配置单独加载，旧任务配置不继续作为当前要求生效。
- 切回旧任务时恢复其目标、配置、资料关联和进展；聊天仍是原来的完整会话。
- 原始历史中可能仍包含其他任务的内容，通过明确当前任务及其范围避免误用，不宣称实现了任务之间的完整上下文隔离。
- 旧任务授权、预算和未完成工具动作不因历史继承而获得继续执行的资格。
- 首版不增加同一个学习任务跨多个会话并行推进的能力。

普通问答或临时插话不自动创建学习任务。通过 UI 创建，或从用户明确要求中识别创建意图；含糊时先说明理解，再由用户确认。

### 2. 交互学习

宽泛的新学习主题，先提供：

1. 对用户目标与用途的理解；
2. 需要澄清的少量关键问题；
3. 有依据、可修改的初始框架。

框架应说明主要方向、必要前置和当前取舍，不宣称已经覆盖整个领域。对易变化、专业性强或存疑的内容，使用已有检索工具核对依据。

用户已给出框架，或正在提出具体问题时，直接进入相应内容，不重复执行完整开场。

后续由主 Agent 根据交流推进，可以解释、举例、比较、发现遗漏、建议下一步，也允许用户跳转和回退。一般回答后等待真人下一条消息，不自动启动无人参与的连续学习。

知识整理与保存继续使用现有草稿、自然语言授权和 UI 操作。用户全程主导仍是可靠保底，不把“主动引导”变成强制课程流程。

### 3. 委托整理

委托整理开始前明确目标、用途、范围、成果形式及初始框架。用户已经明确授权自主细化并开始时，不重复索取相同确认。

任务将框架组织为有限的知识单元及必要依赖。一个单元可以形成一篇文档，也可以是组成连贯文档的一组内容，不按标题机械切碎。

采用三种职责：

| 角色 | 职责与边界 |
|---|---|
| **主 Agent** | 与真人交流、检索、解释、组织内容、处理追问、修订和提交成果。 |
| **读者子 Agent** | 根据学习配置找理解障碍、缺少的前置、例子和衔接，提出有价值的追问；不能代表真人授权或宣称用户已经理解。 |
| **审读子 Agent** | 独立读取完整草稿，对照任务要求、知识库规则和必要来源检查，返回问题与依据。 |

不增加一个只负责转发和调度的管理模型。持续推进由程序协调，内容判断仍由主 Agent 和子 Agent 完成。

每个单元的基本闭环为：

```text
任务范围、单元目标和学习配置
        ↓
主 Agent 获取资料、解释并形成内容
        ↓
读者提出追问 → 主 Agent 补充与修订
        ↓
形成完整草稿
        ↓
独立审读 → 必要修订与复核
        ↓
检查版本、问题和真实授权
        ↓
保存成果，推进下一单元
```

这是业务边界，不要求模型按固定顺序调用每个具体工具。

沿用旧计划默认值：

- 每单元最多两轮读者追问、两轮审读修订，可以提前结束。
- 次数耗尽不等于检查通过。
- 关键问题未解决时保留草稿和原因，停止该单元自动发布。
- 不依赖受阻单元的内容可以继续；最终如实显示部分完成及未解决事项。
- 不默认要求专用网络研究子 Agent 参与每个单元。

### 4. 审读与正式保存

**委托整理的自动发布必须对应实际审读过的版本。**

审读记录至少关联任务要求版本、草稿修订、正文哈希、审读角色与子运行、发现的问题及处理结果。修改正文或相关要求后，原通过记录不能继续用于自动发布。

执行要求：

- 委派时由程序绑定当前单元和固定草稿，不从自由文本中猜测审读对象。
- 审读者获得完整正文；超过单次输入范围时使用现有产物与分页补读，记录实际提供或读取的范围。
- 报告来自真实执行的审读子运行，使用结构化结果；主 Agent 不能自行填写“审读通过”。
- 模型报告、执行状态和程序可验证条件分别保存。子运行结束、正文读取完整都不等于内容必然正确。
- 业务发布工具、通用文件同步及其他正式发布入口共用检查。
- 检查失败保留工作文件和草稿，不覆盖用户修改或隐藏失败。

任务级自动保存许可绑定已确认的任务范围及授权版本。显著扩大范围、合并拆分或批量归档继续遵循现有影响确认规则。

用户可以明确接管并确认某一具体草稿，沿用人工发布路径；记录其为人工决定，不伪称自动审读通过。交互学习和普通任务不被强制套上委托整理的双子 Agent 流程。

### 5. 自动推进、真人介入与恢复

复用现有消息选择：

- **排队**：当前运行结束后处理。
- **引导当前任务**：沿现有安全点机制插入当前运行。

自动推进增加以下规则：

- 准备下一轮时，优先处理同会话已排队的真人消息。
- 普通追问处理完后可以继续原整理；暂停、取消、切换或需要真人决定时停止相关自动推进。
- 已经领取的运行不因后来到达的普通排队消息自动变成即时引导。
- 自动触发有独立来源和推进记录，不创建伪造的真人消息，不参与用户偏好证据提取。
- 用户消息序号与实际运行执行顺序分开处理，自动运行不能破坏现有引导去重和延续快照顺序。
- 协调层依据持久状态和业务回执推进；重复通知、重复结束回调不能创建重复步骤。
- 没有可执行步骤或没有产生有效进展时停止续跑，反馈原因，不反复创建空运行。

暂停保留进展；取消停止后续工作，但不撤销已经完成的保存。关闭浏览器不取消后台工作。服务异常重启后，运行及自动推进都等待用户手动恢复，不自动重新开始收费执行。

保留每 Run 预算，并增加知识单元跨 Run 的累计预算，覆盖主模型、子模型、重试和相关摘要。默认单元上限沿用旧计划：40 次模型请求、80 次工具尝试、20 次搜索、1,200 秒活跃时间。恢复或换一个 Run 不清零；这不恢复已废弃的项目累计次数限制。

## 三、通用长期记忆、学习配置与完整模型输入

### 1. 在现有偏好服务上扩展通用长期记忆

通用长期记忆覆盖：

- 表达与交互偏好；
- 用户明确陈述的背景、经验和知识基础；
- 稳定的协作与思考习惯；
- 跨会话持续的关注方向和目标；
- 可复用的用户纠正。

学习习惯属于其中一种应用分类。知识正文、网页事实、执行日志、当前草稿和工具输出不因此转存为用户长期记忆。

新增记忆需要保存类别、适用范围、状态、来源证据、修订与取代关系、确认时间及必要的复查信息。可以形成有来源关联的简要用户背景摘要，但不能由模型自由编造“用户画像”。

记忆中的用户能力仅允许记录用户自述及明确确认；完成一篇文档或一次任务，不能推断用户已经掌握相关知识。

### 2. 提取时机与更新方式

**继续复用新真人消息的语义解释入口，不在每次主模型调用时另做一次提取。**

同一次结构化解释分别输出：

- 当前操作和任务控制意图；
- 通用长期记忆变更候选；
- 当前学习任务配置变更候选。

三类结果独立校验，记忆错误不能扩大业务授权，也不能因为某个偏好候选无效就丢弃已明确的其他选择。

提取输入包括当前真人消息、必要的上下文、相关既有记忆与配置，不能每次把所有历史和全部记忆无上限塞入。

更新规则：

- 明确、长期适用、无冲突的信息可以生效。
- 当前任务用途、范围、自述基础及要求进入任务配置，不自动提升为全局要求。
- 单次要求保留在本轮上下文。
- 稳定习惯的推断需要多个独立真人证据。默认至少两条、来自不同任务或会话，且仅允许无冲突的表达与互动习惯自动启用；其余推断待确认。
- 用户明确纠正或撤回可形成替代；新记录未成功保存前，不停用旧记录。
- 相同消息重复处理不新增记忆；模型看到、检索到或引用了既有记忆，不算新增确认。
- 读者和审读子 Agent 的输出、自动推进内容、模拟满意度不属于真人反馈。

人工录入、编辑、停用、删除、确认和回退不调用模型。提取失败不循环重试争取一次成功，保留现有记录与失败原因。

### 3. 去重、冲突、过时信息与来源维护

复用现有来源与版本机制，扩展为统一维护流程：

- 完全重复记录合并证据，不制造多条相同记忆。
- 相似但范围不同的记录分别保留，不把“本任务例外”当成全局偏好的撤回。
- 语义合并保留原记录、来源和合并关系，可以回退；不采用删除原内容的有损合并。
- 人工编辑和导入内容不能被模糊推断静默覆盖。
- 对可能过时的背景和目标记录复查状态；默认以 90 天作为复查提示，稳定偏好及明确纠正不按时间直接失效。
- 复查可以随有新真人证据的提取一并提出，不新增定时收费扫描。
- 停用或删除后，从后续检索、背景摘要和学习配置的自动部分移除；派生内容同步失效，避免从另一份摘要重新带回。

历史消息和历史修订仍作为历史保存。停止主动使用某条记忆，不宣称已经物理删除所有曾包含它的对话。

### 4. 相关记忆怎样进入模型上下文

新增统一的记忆选择入口，供主 Agent、读者角色和记忆查询工具使用：

```text
当前真实问题／已确认的学习单元目标
        ↓
过滤状态、适用范围与当前可用版本
        ↓
PG BM25 召回相关记忆
        ↓
结合相关性、来源可信程度和明确纠正进行选择
        ↓
去重、限制 token 数、保留来源
        ↓
加入本次模型可见背景
```

具体采用：

- 继续使用 PG，不增加 SQLite、向量库或 embedding 服务。
- 复用已有中文分词、BM25 与派生索引更新方式，记忆使用独立记录及索引，不混入知识正文检索。
- 摘取 DeerMem 适用的纯函数排序逻辑，在候选集合上结合相关性与置信信息；置信度只是排序信号，不能替代真实证据或决定授权。
- 每次新真人消息或单元目标变化时重新选择；同一运行内无相关变化时复用选择结果，调用前仍检查撤回。
- 默认自动长期记忆注入预算为 **2,000 tokens**，其中最多预留 **500 tokens** 给适用的明确纠正，整体仍不超过该预算。完整请求继续受原容量检查约束。
- 未被自动选中的记忆可通过 `memory_search`、`memory_read` 按需读取，纳入现有工具管理、只读边界和调用预算。
- 不为记忆排序新增模型重排请求，不宣称每轮都自动语义理解并筛完所有聊天。

DeerFlow 的相关性排序本身是可配置能力，并非所有默认运行都会采用。本项目明确选择启用这一类能力，并通过确定性夹具验证排序与范围，而不是把参考项目名称当效果证明。[配置依据](https://github.com/bytedance/deer-flow/blob/3f7a076972a927b4256df3e3c18b829186dd1355/backend/packages/harness/deerflow/agents/memory/backends/deermem/deermem/config.py)

### 5. 两层学习配置与读者角色文档

保留两层用户可理解的配置：

| 配置 | 内容 |
|---|---|
| **通用学习配置** | 默认解释与追问方法、人工偏好，以及从通用长期记忆中选出的学习习惯。 |
| **任务个性化配置** | 本任务的用途、范围、自述基础、重点、详略、例子和成果要求。 |

任务配置长期保存，不因任务结束而删除；可以在新任务中明确选择复用，但不自动变为全局偏好。

有效读者角色由以下内容组成：

```text
项目维护的读者职责与边界
＋ 通用学习配置
＋ 当前任务个性化配置
＋ 当前知识单元与待检查内容
```

主 Agent 同样读取有关讲解与整理要求，避免读者按一套偏好提问、主 Agent 按另一套方式写作。

文档处理采用明确的所有权区分：

- **人工部分**保存用户手写、导入及明确修改的内容。
- **自动部分**由已生效的相关记忆确定性生成，并关联记忆 ID 和版本。
- 自动更新只刷新自动部分，不整体重写人工正文。
- 用户修改自动条目时，转为明确人工修订，并更新关联记忆或任务配置。
- 导出的完整 Markdown 可以查看和携带；有效内容由同一个配置服务管理，不形成文件和 PG 两套可独立编辑的真相。

两层配置均支持聊天修改、UI 编辑、版本对比、导入、导出、停用和恢复旧版本。导入 Markdown 或 `SKILL.md` 风格说明时，先展示内容与适用范围，再由用户应用；只导入说明，不执行附带脚本，不自动启用工具或外部服务。

配置正文的不可变版本保存到现有挂载工作区，PG 保存身份、版本、哈希、来源和关联。任务进展及运行日志不塞入角色文档。

### 6. 本轮模型输入如何组织

保持当前装配分工，增加必要背景，不把所有内容改写成系统提示：

```text
系统指令
  核心行为、知识库规则、模式规则、角色职责

应用补充背景
  当前学习任务与单元
  当前生效的两层学习配置
  相关长期记忆及来源
  进展、计划、任务笔记、资料与产物引用
  读者问题、审读结果和未解决事项

已有工作摘要（存在压缩时）

按原角色与顺序保留的对话和工具消息

本轮允许使用的工具定义
```

背景、摘要、检索材料和自动推进说明均标明来源，不伪装成真人新增授权。原有 256K 工作窗口、90% 压缩阈值、完整工具消息组及历史补读机制保持不变。

同一记忆已经进入学习配置自动部分时，不再重复注入另一份相同内容。手工规则和必需任务配置不能被悄悄截断；容量不足时明确报告并要求缩小或分段。

普通配置修改供下一 Run 使用；当前真人即时纠正仍通过已有引导机制生效。停用、撤回和授权变化在下一相关调用前重新检查。恢复使用原版本依据，不偷偷换成最新配置。

## 四、实现分工、接口、迁移与实施依赖

### 1. 模块职责

| 模块 | 本轮职责 |
|---|---|
| **长期记忆服务** | 扩展现有偏好服务，统一候选校验、来源、版本、替代、停用、检索和背景选择。 |
| **学习配置服务** | 管理通用／任务配置、人工与自动内容、文档版本、导入导出和有效角色装配。 |
| **学习任务服务** | 管理任务范围、模式、框架、单元依赖、状态、成果与任务级授权。 |
| **持续推进协调层** | 在既有运行服务与队列上安排后续步骤，处理真人优先、幂等、暂停恢复和单元预算。 |
| **上下文装配** | 在已有资源快照和动态背景中加入任务、配置、相关记忆及协作记录。 |
| **子 Agent 适配** | 配置读者／审读角色，绑定固定输入，保存结构化报告及真实子运行关联。 |
| **知识发布服务** | 对委托自动发布增加统一审读检查，继续复用版本、引用、文件和索引事务。 |
| **Web 交互** | 显示任务与模式、进展和成果，提供记忆与配置管理，展示必要的追问、问题和恢复入口。 |

业务控制通过服务完成。模型可以提出下一步、更新工作计划和请求委派，但不能直接把自己标记为获得授权、通过审读或任务全部完成。

### 2. 主要接口与类型变化

新增以下接口组，继续使用现有 FastAPI、修订号和请求幂等方式：

| 接口组 | 最小能力 |
|---|---|
| `/api/learning-tasks` | 创建、查询、修改目标与框架、确认、切换模式、暂停、继续、取消及查询单元和成果。 |
| `/api/memories` | 查询、编辑、确认候选、停用／删除、修订历史和相关性查询。 |
| `/api/learning-profiles` | 通用及任务配置、版本、导入预览与应用、导出、回退、有效配置预览。 |
| 学习任务协作查询 | 读取读者问题、审读报告、对应草稿及未解决事项。 |
| 既有聊天接口扩展 | 可选学习任务关联，保留排队／引导选择及旧调用兼容。 |

现有偏好 API 保留兼容入口，映射到统一记忆服务中的偏好类别，不继续维护独立写入逻辑。

运行数据增加可选的学习任务、知识单元、触发来源及实际执行顺序关联。自动推进不占用真人消息身份。旧会话、普通 Run 和原有子 Agent 不要求补齐新的学习业务字段。

读者与审读角色仍通过现有子 Agent 目录管理；角色提示可编辑，业务身份、只读限制和报告来源不能靠提示词伪造。关闭必要角色或工具后，委托任务明确等待处理，不静默重新开启。

### 3. 数据迁移与兼容

采用增量迁移，不清空正常数据：

1. 扩展现有偏好存储，旧记录保留 ID、正文、范围、状态、来源、版本与提取回执，默认归为偏好类别。
2. 增加来源证据关联、记忆检索所需字段及派生索引；人工记录没有原消息时保留人工来源，不补造聊天证据。
3. 新增学习任务、单元、配置版本、协作报告、任务授权与推进记录。
4. 为 Run、草稿及成果增加可空学习业务关联；旧记录保持原含义。
5. 运行快照与延续格式增加兼容读取。旧资源快照不重写，不伪造当时不存在的配置；不能可靠恢复的旧执行明确保留成果并提示以新运行继续。
6. 不自动扫描全部旧聊天提取记忆，不自动把历史会话转换成学习任务。
7. 旧偏好供配置装配直接引用，不批量改写成新文档，更不制造两份独立偏好副本。

迁移前使用现有备份能力。在隔离测试数据库验证非空升级、版本关系、提取去重、旧接口与旧快照兼容。索引可以重建，业务记忆和人工配置不能依赖缓存恢复。

### 4. 按依赖顺序实施

| 顺序 | 具体产物与工作 | 完成条件 |
|---|---|---|
| **1. 固定合同与兼容基线** | 固定本计划、模型输入分工、角色职责及上游采用记录；建立必要接口和迁移合同测试。 | 能区分真人／自动／子 Agent 来源，旧业务不被学习模式接管。 |
| **2. 扩展通用长期记忆** | 完成分类、证据、版本维护、提取改造、PG 索引、相关性选择及旧偏好兼容。 | 多种真实用户信息能按范围保存；错误候选、临时要求和撤回回放不能错误生效。 |
| **3. 建立学习任务与两层配置** | 完成任务／单元数据、配置文档版本、导入导出、人工与自动部分及有效配置装配。 | 配置重启后保留；同会话切换任务不清空历史，不误用旧任务要求。 |
| **4. 打通交互学习** | 接入模式提示、框架引导、任务配置与相关记忆，复用现有 Skills、聊天和发布流程。 | 宽泛主题得到框架；具体问题直接回答；用户能改变方向和决定整理。 |

| **7. 完成 Web 闭环** | 完成模式与任务视图、记忆和配置页面、成果及协作详情、暂停恢复和冲突反馈。 | 用户可通过聊天与必要 UI 完成主要操作，不依赖数据库手改。 |

## 五、验收、交付和后续长期目标

### 1. 必须通过的工程验收

| 场景 | 可验证结果 |
|---|---|
| 普通聊天兼容 | 不强制创建学习任务，不强制委派或入库。 |
| 两任务共用会话 | 历史持续存在；当前配置、框架和进展切换正确，旧授权不串用。 |
| 记忆提取 | 用户自述、明确偏好、临时要求、主题例外、含糊推断分别得到正确状态。 |
| 证据真实性 | 助手回复、读者问题、工具结果、自动推进内容不能成为真人学习偏好的证据。 |
| 更新与撤回 | 重复消息不重复写入；替代原子完成；删除后不能由旧提取或派生文档复活。 |
| 相关性选择 | 中文查询、范围过滤、纠正保留、重复消除与 token 预算可确定性验证。 |
| 配置文档 | 编辑、导入、导出、冲突、回退可用；自动更新保留人工内容。 |
| 角色隔离 | 子 Agent 不继承完整父 State，不获得知识发布、偏好修改或递归委派权限。 |
| 审读发布 | 对应完整草稿与真实子运行；正文变化后旧结果失效，文件同步不能绕过检查。 |
| 真人介入 | 排队保持排队语义；即时引导只应用一次；自动推进不持续抢占真人消息。 |
| 暂停与恢复 | 暂停、撤回、关闭必要工具及服务重启均阻止未经许可的后续动作。 |
| 幂等与预算 | 重复通知、完成回调和恢复不重复创建步骤或成果，同一单元不因新 Run 重置预算。 |
| 任务完成判断 | 执行停止、草稿完成、正式发布、部分完成与等待真人明确区分。 |

### 2. 验证方式与费用边界
