# KnowledgeOps Agent：Harness 可靠性与异步协作增量实施计划

## 一、目标、已确认取舍与复用原则

在现有应用上补齐文件修改可靠性、暂停与恢复、Skill 故障隔离、用户补问、子 Agent 异步管理和 MCP 接入，并完善完整模型输入的预算分配。

本计划针对 `D:\codes\KnowledgeOps Agent`。2026-10-15 用户确认本计划并开启长期目标，现进入实施阶段。此前的[执行权限计划](implementation-plan-permissions.source.md)保留为历史资料；已交付合同继续有效，冲突部分以本计划为准。实施状态与验收证据见 progress.md，计划本身不证明已完成。

已确认的行为：

- 用户暂停时，正在接收的模型响应继续收完并保存，后续模型和工具操作停止；恢复不额外添加“任务暂停过”的用户消息。
- 同一轮模型同时提出询问用户和执行其他工具时，先询问，阻止同批其他操作。
- 本轮加入子 Agent 异步管理：启动、查看、补充要求、取消、读取结果和等待。
- 主 Agent 等待子任务时，子任务完成后自动接续原任务；不通过反复调用模型查询状态。
- 命令工具保持独立短命令，不增加持续终端、stdin 交互或长驻服务管理。
- 保持 **262,144 tokens 工作窗口、90% 压缩触发阈值**。
- 保持现有单任务预算、只读子 Agent、非递归委派及权限上限。异步执行不获得额外额度。
- 验证优先零付费；用户2026-10-15澄清允许必要的小范围真实模型调用，不以零付费作为硬性禁令。

相对旧计划的重要变化：原来延期的动态工具搜索，本轮纳入；子任务从同步等待扩展为可管理的异步运行；新增通用文件操作回执、明确的暂停状态和结构化补问。已经交付的审批、消息插入与排队、长期记忆、知识发布和 MCP 会话池继续复用。

复用方式明确如下：

| 方式 | 使用内容 |
|---|---|
| 直接复用 | LangChain 工具与中间件接口、LangGraph 检查点和中断恢复、Deep Agents 的 Skills／文件工具／同步委派中间件、MCPAdapter、FastMCP、现有 PG／Celery／Redis |
| 摘取并适配 | DeerFlow 的读取后修改检查、询问时阻断同批操作、延迟工具 Schema 加载；保留来源与许可说明，适配本项目身份、状态和权限 |
| 应用层新增 | 文件回执、统一补问记录、本地异步子任务调度、结果通知和背景预算分配 |

本轮已核对 DeerFlow `8d994cc1`、Deep Agents `825acb3c`。DeerFlow 相关中间件及测试与此前审查版本一致。Deep Agents 的异步中间件依赖 Agent Protocol 服务，因此本项目复用其公开工具参数与交互设计，调度接入现有运行服务，不为使用该中间件另建一套 Agent Protocol 服务。[Deep Agents 异步接口](https://reference.langchain.com/python/deepagents/middleware/async_subagents/AsyncSubAgentMiddleware)

## 二、模块职责与行为设计

### 1．文件修改：检查版本，保存执行回执

由文件工具中间件负责“是否读过当前版本”，由工作区操作服务负责实际修改及恢复，知识同步模块继续负责草稿、版本和发布规则。

- 成功读取文件时，将规范化路径、工作区身份和整文件哈希附在读取结果上。修改已有文件前，检查当前文件是否仍为读取时的版本。
- 新建文件必须确认目标不存在；已有文件的覆盖、编辑、删除均经过检查。修改成功后旧读取标记失效。
- 对同一路径串行执行“读取及标记”或“检查及修改”，防止同批并行工具同时通过旧版本检查。
- 历史压缩移除读取正文后，相应读取标记也失效，模型需要重读。不能只在数据库留下“曾经读过”就永久放行。
- 检查无法完成时返回明确错误和重读建议；不照搬上游的失败放行策略。

参考 DeerFlow 的读取标记、路径锁及压缩后失效设计。[读取后修改中间件](https://github.com/bytedance/deer-flow/blob/8d994cc1e7ee63c61283a71a169248beb4ed1c52/backend/packages/harness/deerflow/agents/middlewares/read_before_write_middleware.py)

新增文件操作回执，绑定真实 Run、工具调用 ID、参数指纹、路径、修改前后哈希及结果：

- 修改前保存执行意图；正文通过同目录临时文件和原子替换写入。
- 已成功的同一调用直接重放结果，不再次修改或扣除工具额度。
- 崩溃后若目标已经等于预期结果，只补齐回执及幂等知识同步。
- 若文件出现第三种内容，停止并报告冲突；已经进入执行阶段却无法证明结果的操作进入待核对状态，不自动重做。
- 文件修改成功但知识同步失败时，保留工作文件，只重试同步，不重放文件修改。

这套保护针对应用文件工具。Shell 仍属于现有审批与命令回执体系，不宣称能识别任意脚本内的文件修改，也不承诺阻止不遵守文件锁的外部编辑器在任意瞬间写入。

### 2．Skill：单包失败不影响正常任务

继续使用现有渐进加载方式：系统提示提供目录，模型通过 `read_file` 读取正文，脚本通过已授权的命令工具执行。

- 将单包解析、资源检查和打包错误隔离，出错包显示不可用原因；其他正常包继续加载。
- 启停策略、兼容性状态和格式错误分别展示，用户不能通过“启用”绕过不兼容或损坏状态。
- 全局启停配置损坏时，Skills 整体停止加载并报告原因，普通聊天仍可运行；不能把配置错误解释为全部启用。
- 必需的系统规则或知识库业务规则缺失，仍按原规则阻止相关业务，不能套用可选 Skill 的容错策略。
- 新运行冻结有效包；旧运行继续使用原快照，实时撤回规则不变。扫描和导入不执行脚本、不安装依赖。

### 3．运行控制：区分暂停、等待和取消

由运行服务保存控制事实，图中间件设置安全停止点，worker 负责释放执行资源和恢复。

新增暂停请求标志，以及 `paused`、`waiting_children`、`waiting_input` 状态；现有审批记录与兼容接口保留。

正常暂停流程：

```text
保存暂停请求
→ 禁止启动新模型和新工具
→ 收完已经发出的模型响应
→ 保存响应及检查点
→ 在执行后续工具之前暂停
→ 用户恢复后继续原位置
```

- 在模型节点之后设置独立停止点，避免通过抛异常丢失刚返回的响应。
- 为模型步骤增加稳定调用身份，复用现有网关回执和原请求快照。响应已保存、图检查点尚未提交时发生故障，恢复应取回原响应，不重复请求供应商。
- 没有新要求或权限变化时，恢复保留原待执行提议；有变化时，先应用新要求并使旧提议失效。
- 暂停传播到整个根任务及其子任务。已启动的本地命令沿现有控制终止进程组并保存输出；无法确认结果的远端调用保留未知状态。
- 取消继续表示放弃尚未执行的提议，与可接续的暂停分开。
- 原有模型超时和网络异常处理继续生效，不因“收完响应”无限等待。
- 服务异常重启仍等待用户明确恢复；正常的子任务完成事件可以自动接续，但不能复活已暂停、取消或失去权限的任务。

### 4．用户补问：接通展示、回答和原任务恢复

新增通用补问记录和 `ask_clarification` 工具。问题、选项、自由文本回答及响应状态持久化，绑定具体 Run、工具调用和要求版本。

- 主 Agent 遇到必须由用户决定的缺口时，通过补问工具提出问题。
- 同批存在补问时，在进入工具执行节点前移除其他待执行提议，保留原始模型输出供追溯；回答后重新决策，不自动执行被阻止的命令。
- 旧检查点直接恢复到工具节点时也有兜底检查。
- 原 `wait_learning_input` 接入同一等待机制，同时保持知识单元的等待状态和原参数兼容。
- 用户主动插入、排队仍走现有入口；结构化回答绑定问题 ID，不把任意新消息当作审批或答案。
- 等待用户时释放执行线程，不计入活跃时间。明确回答后通过原 outbox 接续一次。
- 执行审批与补问在 UI 中采用一致的待处理展示，但审批事实仍保存在原权限模块，不把回答问题等同于授权。

参考 DeerFlow 的补问拦截与同批工具处理，适配现有消息协议和恢复机制。[补问中间件](https://github.com/bytedance/deer-flow/blob/8d994cc1e7ee63c61283a71a169248beb4ed1c52/backend/packages/harness/deerflow/agents/middlewares/clarification_middleware.py)

### 5．主子 Agent 并发：同一 worker 内持久调度

采用**一个 worker 进程、三个 Agent 执行槽**，默认容纳一个主 Agent 和两个子 Agent。Celery 使用受控线程并发，数据库继续限制同一时刻只有一个活跃根任务组；不增加容器或独立调度服务。

- 子任务也创建持久 Run 和 dispatch，由 worker 独立领取，使用自己的检查点连接、消息历史和执行身份。
- 启动异步子任务立即返回任务 ID，主 Agent 可以继续独立工作。
- 根任务等待子结果时不占执行线程；子任务仍可运行。运行守卫明确区分这种等待与用户暂停。
- 主子任务的模型、工具和搜索额度原子共享。保留主任务收尾请求的预留，子任务不得抢占收尾额度。
- 活跃时间按整个任务组实际运行时间计算，并发重叠不重复累加；全部等待真人或暂停时停止计时。
- 追加给子任务的指令持久化，在安全点应用，并使旧决策失效。来源标为主 Agent 或真人，不能伪装为用户偏好证据。
- 子任务默认继承根任务允许的只读 MCP 能力，角色工具组可以收窄；不增加 Shell、知识发布或递归委派权限。
- 主子 Agent 复用同一个 MCP 接入模块，但子 Agent 使用独立会话范围，不共享同一个可变浏览器会话。
- 同步 `task`、历史委派和学习协作入口保留，改为调用同一持久委派服务；等待时保存图状态，不再维持第二套线程池生命周期。

模型可使用以下工具：

| 工具 | 行为 |
|---|---|
| `start_async_task` | 选择已配置角色并启动任务，立即返回 ID |
| `check_async_task` | 查看单个任务状态和已有结果 |
| `list_async_tasks` | 查看当前根任务的子任务 |
| `update_async_task` | 向未结束的子任务追加指令 |
| `cancel_async_task` | 取消指定子任务，不影响其他子任务 |
| `wait_async_tasks` | 等待指定任务中的任一个或全部完成，默认全部；释放执行线程 |

完成事件采用以下数据流：

```text
子任务保存结果
→ PG 保存完成事件与去重身份
→ 主任务运行中：下一安全点接收结果通知
→ 主任务等待中：outbox 唤醒原 Run
→ 主 Agent 阅读结果并继续
```

通知只携带状态、摘要和结果引用，不把整个子任务历史塞入主上下文。消费位置绑定检查点，避免通知重复或结果丢失。

根任务不能在子任务仍运行时悄悄完成并留下后台收费活动。主 Agent 应等待其收束，或明确取消不再需要的子任务。子任务失败作为真实结果反馈，不伪装成功，也不自动无限重试。

### 6．MCP 补问：保存协议续接状态

继续使用现有 MCPAdapter、FastMCP、连接池和调用回执。

- 对现代协议的 `InputRequiredResult`，保存补问内容、轮次、原调用身份及服务端续接状态；图进入等待，不返回伪造的工具成功。
- 用户回答后，使用原续接状态及 `input_responses` 发送后续协议轮，不重新发送没有答案的首轮请求。
- 调用桥接使用官方客户端公开的 session 与协议类型，不修改 SDK 私有实现或重写传输层。
- 普通字段表单和 URL 补问均提供用户入口；URL 操作由用户进行，服务是否完成由服务端确认。
- 不将不透明续接状态、凭据或认证信息注入模型提示和普通日志。
- 每次继续都复查服务配置、Schema、权限和任务控制。配置失效、取消、结果不确定时沿用原未知结果处理，不自动重发外部操作。

兼容范围明确：本轮完成能够保存并续接的补问路径。旧式依赖活连接的服务端补问，不承诺进程重启后的恢复；当前 SDK 不支持的路径须明确报告兼容限制，不能伪装成用户拒绝或无限等待。普通 legacy MCP 工具和已有会话复用继续可用。

### 7．上下文：统一预算，分别处理背景与历史

由上下文装配模块生成候选材料，预算分配器决定本轮可见内容，现有压缩模块处理需要摘要的历史。

- 增加系统规则、必需背景、可选背景、历史、工具 Schema、输出预留的 token 分项记录；总量仍由实际模型请求的计数路径校验。
- 当前请求、尚未处理的有效要求和完整工具调用关系优先保留。只确定性去重或按明确修订替换要求，不根据“比较旧”就判定失效。
- 证据目录按当前材料、使用记录和检索相关性选择；合并重复文档版本，保留引用与补读入口。新增分页证据目录工具，省略的目录项仍可查找。
- 长期记忆、任务笔记延续原有范围与相关性规则，不建立第二套记忆系统。
- 先缩减重复、低相关、可补读的背景，再压缩历史；不能只让历史给无限增长的背景让位。
- 压缩触发仍为 90%；压缩后的输入目标默认 80%，根据剩余空间保留最长的完整近期消息后缀，替代固定保留约 10% 窗口历史的策略。
- 可选背景的压力缩减目标默认 `min(16,384 tokens, 工作窗口的 1/8)`，必需要求不计入该可选额度。这是可配置的工程初值，不宣称是行业标准。
- 必需信息本身已经超过容量时，明确要求缩小材料或拆分任务，不静默丢弃要求，也不连续调用模型尝试无效摘要。

延迟工具加载：

- 本地核心工具保持直接可见；可选 MCP 工具默认经 `tool_search` 发现后加载 Schema。
- 检索仅覆盖本运行已授权、已冻结的工具目录；不联网搜索安装新工具，也不额外调用模型进行路由。
- 已加载工具集合绑定目录哈希和当前 Run。上下文紧张时可以移除不再使用的可选 Schema，保留再次发现入口。
- Schema 未加载不能绕过执行检查；工具停用或撤回始终优先，主子 Agent 分别维护自己的加载集合。

参考 DeerFlow 的 Schema 过滤、目录版本绑定和执行前检查。[延迟工具过滤中间件](https://github.com/bytedance/deer-flow/blob/8d994cc1e7ee63c61283a71a169248beb4ed1c52/backend/packages/harness/deerflow/agents/middlewares/deferred_tool_filter_middleware.py)

### 8．命令输出：保存完整可补读结果

保留现有短命令、超时、取消和进程回收机制。

- stdout／stderr 边接收边写入运行产物，避免先截断后才保存。
- 默认最多保存 10 MiB 输出，模型只接收有界预览及产物引用；超过保存上限时继续排空管道，并明确记录截断原因。
- 复用已有产物读取和分页补读，不把完整输出重复存入数据库正文或模型上下文。
- 超时、取消和异常同样保留已收到的输出、退出状态和截断标记。
- 不增加交互式终端、后台服务常驻或跨调用 Shell 环境继承。

## 三、接口、前端与数据迁移

**接口增量**

- 增加 Run 暂停入口，复用恢复入口；保留取消接口原有语义。
- 增加根任务补问列表与回答提交接口，回答绑定问题身份、修订和合法响应类型。
- 增加子任务列表、详情、追加指令和取消接口；模型工具与 UI 调用同一服务层。
- 原执行审批接口、知识发布接口和消息插入／排队接口保持兼容。
- 运行事件增加暂停进度、补问待办、子任务变化及结果就绪信息；沿用 PG 事件与 Redis SSE 桥。

**前端**

- 主聊天提供暂停／继续，并区分“正在收尾暂停”“等待用户”“等待子任务”。
- 会话内展示子任务卡片：角色、目标、状态、必要进度、结果、补充要求和取消。
- 提问卡与原审批卡共同出现在待处理区域，但明确区分回答信息与批准操作。
- 刷新后从服务端恢复状态，不依赖浏览器保持打开。
- 上下文百分比继续显示，可展开查看组成；不展示原始提示、凭据或开发验收报告。

**持久化增量**

复用 Run、dispatch、事件、检查点、工具预算和 MCPCall，新增或扩展：

- 文件操作回执及不可变修改内容引用。
- Run 暂停／等待控制字段。
- 补问、回答和 MCP 协议续接记录。
- 子任务追加指令、结果通知去重及消费位置。
- 检查点中的模型步骤身份、文件读取标记及已加载工具集合。

文件正文和输出继续保存在挂载工作区；PG 保存身份、控制事实、哈希、版本和引用。Redis 不成为事实来源。

**迁移与旧任务兼容**

- 以当前迁移版本为基础增加迁移，不清库、不重建卷、不复制全部聊天历史。
- 已完成历史保留原状，不回填虚假的读取、批准或执行记录。
- 旧资源快照不自动增加新角色能力或 MCP 权限；新能力从新根任务开始冻结。
- 旧同步工具名和参数继续可恢复。缺少读取标记时要求重读；缺少可信执行回执时不能猜测已经成功或尚未执行。
- 暂停、等待、取消与异常恢复分别测试，更新所有依赖终态判断的调度、学习推进和前端逻辑。
- 新环境配置同时接入读取代码、示例和说明；真实 `.env` 只补缺项，保留已有值和密钥。

## 四、实施顺序与依赖

| 阶段 | 工作 | 完成后提供的基础 |
|---|---|---|
| A：状态与持久化 | 固化本计划，增加暂停、等待、补问、回执及兼容迁移 | 后续模块共用的控制与恢复合同 |
| B：文件与 Skill | 文件版本检查、操作回执、知识同步恢复、Skill 故障隔离 | 可独立验证的可靠性改进 |
| C：暂停与交互 | 模型步骤身份、安全暂停点、补问 UI、同批操作阻断 | 主子任务统一的停止与人工交互机制 |
| D：异步子任务 | 三槽 worker、独立领取、共享预算、管理工具、事件唤醒、同步入口兼容 | 完整主子并发闭环 |
| E：MCP 接续 | 子角色能力筛选、独立会话范围、补问续接及失效处理 | 主子 Agent 一致的 MCP 能力 |
| F：上下文与输出 | 分项计数、背景筛选、历史保留调整、工具搜索、输出落盘 | 新增状态和工具下的完整输入管理 |
| G：兼容与交付 | 跨模块离线闭环、迁移核验、文档同步、遗留边界核对 | 可审查的完整交付 |

阶段 B 可与状态设计分别推进；D 依赖 A、C；E 的用户补问依赖 C，子角色接入依赖 D；F 在新增工具与状态合同稳定后完成。

边开发边验证。正式迁移前保存现有备份并停止相关应用进程，完成后按原开发方式启动；不把本轮扩大为重新部署整套环境。

## 五、验收条件、交付与执行边界

| 编号 | 必须证明的行为 |
|---|---|
| H01 文件冲突 | 读取后被其他操作修改，旧写入被阻止；同批同路径操作不能同时通过旧标记 |
| H02 文件恢复 | 修改后、回执前或知识同步前故障，恢复不重复修改；冲突和未知状态不会自动覆盖 |
| H03 Skill 隔离 | 单包损坏不阻止正常任务；启停配置损坏不会放开全部技能 |
| H04 安全暂停 | 模型流中暂停后响应保留，后续工具未执行；恢复不重复请求已保存的响应 |
| H05 补问 | 同批询问与命令中，命令零副作用；回答、拒绝、取消、刷新和重复提交均正确 |
| H06 真实并发 | 模型替身用同步屏障证明主 Agent 和两个子 Agent 可同时推进；并发上限由数据库约束 |
| H07 共享预算 | 并发请求不能超额，等待不重复计时，恢复和追加指令不清零预算 |
| H08 子任务管理 | 启动立即返回；追加要求使旧决定失效；单独取消不误停其他任务；禁止递归和越权 |
| H09 事件接续 | 子结果唤醒原根任务，重复事件不重复接续；主任务暂停时结果不能使其自动复活 |
| H10 MCP | 子角色仅获得允许的工具，会话不串用；补问回答进入后续协议轮，测试服务计数证明首轮未重复执行 |
| H11 上下文 | 完整请求计入全部组成；大背景先筛选；近期完整消息保留；工具搜索不能绕过撤回和角色上限 |
| H12 输出保存 | 预览截断后仍能补读保存上限内的完整输出；超限、超时和取消均有真实标记 |
| H13 迁移兼容 | 旧会话、检查点、同步委派、消息插入／排队、审批和知识发布继续工作 |
| H14 界面闭环 | 浏览器验证暂停、补问、子任务管理、刷新恢复和结果接续，不只检查后端返回值 |

验证使用真实业务模块、图、隔离 PG／文件、临时本地 MCP 服务和确定性模型替身。上下文使用约 1–2 万 tokens 的测试窗口验证算法，不消耗真实 256K 模型输入。新增持久状态须覆盖进程重启和重复投递，不能仅靠内存单元测试。

每阶段运行受影响检查，最终完成一轮覆盖本计划及关键兼容路径的离线验收。稳定后对替身无法证明的供应商协议、工具理解及实际协作做必要的小范围真实验证，发起前说明具体目的和预计请求数；不重跑大批效果实验，不无假设重复调用。未覆盖的真实语义效果仍单独标明，较大费用另行确认。

交付包括：

- 更新后的实施计划及验收对应表。
- 沿真实运行顺序编写的开发实现说明，解释模块如何协作、参考了什么、哪些直接复用、哪些进行了适配。
- 当前状态、必要验证证据和剩余限制。
- 暂停、异步子任务、MCP 补问及新增配置的使用说明。

明确不包含：交互式终端、AIO／操作系统级沙盒、递归委派、多租户、向量检索、新数据库、自动安装第三方 MCP、供应商自动重试、关闭的辅助模型效果实验，以及旧式 MCP 补问跨进程恢复的保证。

不修改个人知识库，不提交或推送 Git，不启用 GitHub CI，不创建额外长期目标。按已授权的当前长期目标实施。
