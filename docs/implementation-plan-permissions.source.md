# KnowledgeOps Agent：Harness 补齐与执行权限实施计划

确认并进入实施：2026-10-14。目标项目：D:\codes\KnowledgeOps Agent。

本文件完整保存本会话确认的增量计划，是本轮唯一实施与验收依据。此前已交付的[学习模式与通用长期记忆计划](implementation-plan-learning-memory.source.md)作为历史资料保留；既有功能合同继续有效，冲突部分以本计划为准。当前实现与验证状态见[进展](progress.md)，计划文字不证明功能已实现。

## 1. 目标和执行边界

在现有 LangChain create_agent / LangGraph、Deep Agents、PG 持久化和 Web 应用上，补齐统一执行权限、人工审批、可靠恢复和配置继承。保留现有工具目录、Skills、长期记忆、会话短期记忆、消息插入/排队、子 Agent、学习协调器、知识发布门和 MCP 管理。

权限指 Agent 是否可以执行具体操作，不是登录、RBAC 或多租户。本轮不增加 AIO、独立沙盒容器、自动审查模型、递归委派、向量/GraphRAG、动态工具搜索或额外数据库。不把 LocalShellBackend 描述成操作系统隔离。

以已核对的成熟接口为优先：直接复用 LangChain HumanInTheLoopMiddleware、LangGraph interrupt / Command(resume=...) 和现有 PG checkpointer；命令匹配借鉴 Codex execpolicy 的确定性参数匹配，复用 tree-sitter Bash 解析器；DeerFlow 用作能力过滤与执行边界复核的设计参照，不整体迁移 Harness。

规划阶段核对的上游版本：DeerFlow a1e3e75b17b0fd73ba42a33b6f135f1710cadabc；Deep Agents f8ecffad6523775a323a807bc57097a98aa27e01；Codex 7b06e4af664049a3c1ed3113c4ee52ec3d5993f2。项目当前锁定 Deep Agents 0.7.23、LangChain 1.4.3；实施核对已安装公开接口及源码，不为“追最新”自动升级现有依赖。必要新增解析依赖须记录理由与许可。

验证默认零付费模型：真实图、真实业务模块、隔离 PG/文件、模型替身、前端与浏览器闭环。开发/依赖/测试均在本项目 dev 容器，不使用共享容器或 Windows Python。不提交/推送 Git，不启用 GitHub CI，不删除业务数据/卷，不读取或修改桌面个人知识库。保留现有未提交改动和真实 .env 值。

## 2. 已确认产品取舍

### 2.1 会话权限模式

提供“请求批准”（默认）和“自动执行”，选择保存到整个会话；后续普通任务、学习自动推进均继承。此选择不是一次 Run 的临时复选框。

请求批准模式：
- 已开放的工作区文件读写、公开网页检索/读取直接执行。
- Shell 命令在执行前请求批准；确认规则匹配时可免于重复批准。
- 外部写操作按现有 MCP 确认策略审批。
- 知识发布继续使用现有草稿/版本/授权流程，不重复增加通用审批。
- 工具禁用、子角色上限、资源撤回、显式 deny 始终优先。

自动执行跳过通用命令询问，不覆盖上述权限上限，不绕过 MCP 明确配置的强制确认和知识发布门。UI 明确当前模式的作用范围。当前 Shell 继承容器进程可访问范围；批准控制“是否启动”，不控制命令启动后的全部文件或网络行为。

### 2.2 一次、本会话和持久命令规则

命令审批支持：允许一次、拒绝一次、按展示规则在本会话允许、将展示规则保存为跨会话规则、停止任务。拒绝一次反馈模型另选方案，不自动变成永久拒绝。

规则保存到确定性的权限配置，绝不作为长期用户记忆；模型、Skill、导入材料、偏好提取不能创建授权规则。规则管理支持 allow / ask / deny、停用和删除。

规则按规范化后的 argv 精确或前缀匹配，同时绑定工作区与 cwd；审批卡必须展示匹配范围，不用字符串 startswith 或模型语义相似判断。首版只对可可靠分析的简单命令开放可复用规则；变量展开、重定向、命令替换、复杂脚本等仅允许单次确认。不生成宽泛 shell / Python / Node 等解释器前缀授权。复杂命令仍可批准一次执行，不以解析能力有限为由删除通用执行能力。

MCP 保留现有“服务修订 + Schema + 精确参数”的单次批准，不扩大为任意外部写权限。

### 2.3 决策和运行边界

同批全部审批有结果后自动继续原执行；不再要求点第二次恢复。等待审批释放 worker，不计入活跃执行时间。取消、用户插入新指令、权限撤回后不得盲目续跑原动作。

现有消息插入/排队交互不重做：插入改变当前任务意图并撤销旧决策，排队保持当前任务后执行的语义。拒绝操作成为 ToolMessage 反馈，不伪造工具成功。服务异常重启仍遵守现有人工恢复规则；已批准待续跑使用持久 outbox，不靠浏览器存活。

### 2.4 延后范围

Skill allowed-tools 强制约束本轮不实现；导入带该声明的包必须显示当前不兼容，不能静默忽略声明继续启用。已有无该声明的 12 个兼容包继续可用。

已完成的供应商思考档位不重做；本轮补齐会话默认值和普通/子 Agent/自动推进的继承。思考选择在新 Run 创建时固定，修改不改变正在执行或恢复中的原模型参数。

## 3. 模块职责及复用边界

| 模块 | 处理方式 | 职责 |
|---|---|---|
| tool_catalog / tool_policy / run_resources | 直接复用并接入 | 稳定工具身份、组/角色上限、冻结资源、实时撤回；审批不能开启未授权工具 |
| execution_policy（新增） | 新增适配 | 根据工具、参数、会话模式、规则、当前撤回状态返回 allow / deny / ask 和理由 |
| command_rules（新增） | 复用解析器、适配存储 | 简单 Shell argv 解析、工作区/cwd 约束、规则规范化和可解释匹配 |
| conversation settings | 改造 | 模式、思考偏好、修订号持久化；新 Run 快照 |
| execution approvals / command receipts | 新增 | 动作指纹、批次、决定、执行回执、未知结果；复用 PG 事务和原事件 |
| LangChain HITL / LangGraph | 直接复用 | 工具提议后中断、持久图状态、按原顺序 Command(resume=...) |
| runtime / worker / delegation | 改造 | 执行前最终复核、识别真实中断、主子运行聚合、拒绝反馈、结果恢复 |
| jobs / dispatch / lease | 改造并复用 | 审批完成后幂等续跑、重复投递防护、不重置预算与授权 |
| mcp_calls | 保留精确审批并适配 | 统一展示与自动续跑；不复制第二套 MCP 审批记录 |
| learning_coordinator | 改造 | 自动根运行继承配置，等待审批不推进下一单元、不另建 Run 绕过 |
| frontend | 薄管理入口 | 会话模式/思考选项、审批卡、规则列表、未知执行结果处置 |
| skill_packages | 小幅改造 | 不支持的 allowed-tools 声明显示不可用 |

权限模块不把全部提示内容当作控制输入。正文、历史、模型理由是信息；用户在 UI/API 的真实决定及部署策略才产生授权。

## 4. 执行数据流

1. 创建/更新会话运行设置，使用修订号防止并发覆盖。新根 Run 冻结模型参数、模式来源与配置修订；子运行继承根快照并取原角色能力上限。
2. 模型返回工具提议。先处理待插入真人消息，再检查工具可用性、角色上限、资源代次和执行策略。
3. 需要审批的动作先保存精确参数指纹、工作区/cwd、意图代次、规则/配置修订、工具调用 ID 与批次顺序，再由 HITL interrupt 保存图中断。
4. worker/子运行适配层读取 StateSnapshot.interrupts，标记 waiting_approval，记录原中断标识。不能把图正常返回的中断状态当成执行完成。
5. 前端从根 Run 聚合主/子 Agent 和 MCP 待办，显示操作、参数、执行者、可复用规则范围；显示脱敏但校验完整参数哈希。
6. 用户提交 action_id、expected fingerprint、决定及作用域。事务锁定原根运行/动作，校验取消、意图、资源、规则修订；保存决定和可选规则。
7. 同批全部决定有效后，用原 dispatch/outbox 只调度一次。恢复按原中断 ID 和动作顺序传递决定；中断重入时固定原批次，不能因规则已变化而跳过原 interrupt。
8. 工具真正开始前再次校验最新 deny/停用/撤回/意图，随后预占执行预算并持久写 running 回执。拒绝不执行工具、不伪造成功，不重复扣额。
9. 完成后保存结果，再给模型 ToolMessage；模型继续规划。长结果仍沿现有产物外置/补读路径。
10. 旧检查点若已停在工具节点，也必须经过执行前守卫；必要时建立兜底审批中断，不因缺少新 after_model 节点而绕过。

改变执行模式/规则在下一工具边界生效；不能撤销已经发生的副作用。取消运行中的命令使用现有进程清理。思考参数只在新 Run 生效。恢复原 Run 不重新冻结配置、不清空预算。

## 5. 命令副作用、故障和未知结果

命令回执与 run_id、tool_call_id、参数哈希、cwd 和授权代次绑定，区分 pending、approved（尚未开始）、running、succeeded/failed、denied、unknown。

已有成功结果重放，不能重复启动相同调用。崩溃可能发生在命令已产生副作用但结果尚未提交时，这种 running 遗留归入 unknown，禁止自动重试，不声称任意 Shell 能严格 exactly-once。

未知状态在 UI 显示原命令及最后已知阶段，用户可以核对后跳过（返回“用户选择跳过，结果未知”，不是成功）或明确批准重试一次。重试另留用户决定和尝试序号；并发点击、重复消息、重复任务投递不能启动两次。停止等待中的任务不允许后来到达的批准复活执行。

主/子 Agent审批归属同一根会话，批准后恢复原子运行；不能创建第二个委派或扩大子角色能力。未提供写工具的只读子 Agent仍只读。

## 6. API 和前端合同

- 会话运行设置 GET/PATCH：权限模式、思考偏好、修订号；前端只使用真实模型支持的选项。
- 根运行审批 GET：聚合类型、执行者、精确参数/预览、状态、动作/批次标识、合法决定、规则候选和指纹；不泄露凭据。
- 决策 POST：动作标识、预期指纹、allow/deny、once/session/persistent 作用域；拒绝过期参数和无效作用域。
- 命令规则 CRUD：工作区/会话作用域、argv 匹配、cwd、allow/ask/deny、启用状态与修订；规则 UI 位于现有能力管理区域。
- 未知命令回执处置：明确 skip/retry，绑定原回执版本。
- 复用 SSE/PG 事件流，增加 approval_required / approval_resolved / execution_policy_changed 等必要用户事件；刷新后从 PG 恢复待办。
- 保留旧 MCP API 合同，兼容入口也触发统一续跑；不要求用户处理两张同一动作审批卡。
- 正常聊天、消息队列、知识发布、Skill 开关、工具组及手动异常恢复保持可用。

界面不暴露 LangGraph 内部数据结构、开发验收报告或模型累计计数。

## 7. 数据迁移和兼容

新增会话运行设置 JSON 与修订号；新增命令规则、审批动作/批次、命令执行回执等必要表/索引/唯一约束。PG 是事实来源，不用长期记忆、Redis 或客户端本地存储充当权限数据库。

复用 runs、events、dispatch、checkpoints 和 MCPCall 表，不迁移或复制全部历史对话。旧会话缺省为请求批准和供应商默认思考；已完成 Run 保持原历史，不能生成虚假的审批。旧未完成检查点按新执行守卫保护，保持原资源快照/预算/已完成结果，缺少新字段不获得自动执行授权。

迁移先在隔离测试数据库演练已有0022结构到新增版本，再核对索引、幂等约束、旧会话及未完成 Run。正式数据使用增量迁移，不清库、不重建卷；需要降级时明确不可无损删除执行事实，沿既有备份方案恢复。

新增可部署参数同时实现读取逻辑、.env.example、README说明；真实.env只补缺项，保留当前值/密钥。业务默认模式尽量放会话配置；不新增无意义的重复开关。

## 8. 实施顺序和依赖

### 阶段 A：规则、配置与持久化基础
保存完整计划与决策，核对当前公开接口。先写权限矩阵、规则匹配、修订并发、旧数据默认行为的离线测试，再实现策略/规则/会话配置和迁移。验收重点是不能由文本授权，deny 与资源上限优先，旧会话安全缺省。

### 阶段 B：真实执行边界及命令回执
接入执行前守卫、预算扣除时机、工作区/cwd规则和持久命令回执；真实本地子进程使用临时文件核对副作用、结果重放、取消及故障未知态。包括旧工具节点检查点的兜底保护。

### 阶段 C：HITL、主子运行和自动恢复
复用 HITL 的批量中断/恢复，改造 worker/delegation 识别中断；复用 jobs/outbox 实现用户决定后的幂等续跑。接入 MCP 原批准/拒绝 API 的自动恢复，测试多个动作、多个子运行、刷新/重启、重复提交。

### 阶段 D：配置继承与产品交互
会话设置影响新普通和自动 Run，子 Agent继承根模型参数/权限上限；权限变更在工具边界即时复核。前端接入模式、审批卡、命令规则、未知结果处置，并保留消息插入/排队和知识发布流程。

### 阶段 E：兼容验证与交付
运行受影响回归、迁移、真实图及浏览器离线闭环。同步架构、README、当前上下文和自然语言开发进展。逐项审计本计划，区分静态/离线/真实网络/模型语义证据。只在全范围完成且有对应证据后结束长期目标。

阶段间边开发边验证，不等到最后才检查。通过且未受影响的测试不反复执行；不跑旧收费全量评估，不用“mock通过”证明语义质量。

## 9. 验收条件

A01. 默认会话可用文件读写/公开检索；Shell 在真实副作用前等待；自动执行与 deny/禁用/角色上限符合矩阵。
A02. 一次批准只对应原调用，本会话规则不泄漏到其他会话，持久规则仅在同工作区与cwd/argv范围内匹配。
A03. shell组合、变量展开、重定向、命令替换、解释器等不获得过宽的可复用授权；复杂命令单次仍可执行。
A04. 参数变化、插入新用户指令、取消、工具关闭、资源撤回使旧批准失效；没有模型或偏好接口能添加权限规则。
A05. 批量审批按原顺序恢复；拒绝反馈模型；等待释放worker且不消耗活跃时间；全批决定后自动续跑。
A06. 重复点击、重复投递、恢复和中断重入不重复调用或扣额，服务重启仍按原人工恢复规则处理未授权任务。
A07. 成功回执可重放；注入“执行后提交前崩溃”进入unknown，不自动执行；用户skip/retry有可追溯决定。
A08. 主/子Run审批在同一会话展示和继续原子运行，仍共享预算；自动学习等待审批不另建Run绕过。
A09. 会话思考设置正确传入新根/子/自动Run，当前Run与恢复保留原参数；权限改变下一工具边界生效。
A10. MCP不重复提示，同一精确调用批准/拒绝后继续；原版本/Schema/参数防重放、unknown和发布授权合同保持。
A11. 旧会话/运行/检查点兼容；迁移不破坏历史；旧checkpoint直接到工具节点也无法绕过新审批。
A12. UI刷新、等待/完成事件、模式切换、规则管理、未知结果处置真实闭环；正常聊天/插入/排队/发布仍可用。
A13. 不支持allowed-tools的包显示不兼容，现有无该声明的兼容Skills继续渐进加载/执行；不实现新的Skill权限系统。
A14. 提交自然语言开发说明，逐处区分直接依赖、源码摘取和设计适配，说明审批与隔离边界及未验证语义能力；最终交付包含全部验收映射与遗留限制。

## 10. 交付及范围纪律

开发实现正文持续维护 docs/architecture.md，沿真实Agent运行与Web协作说明，不用命令流水代替解释。docs/progress.md概括阶段状态及证据入口，PROJECT_CONTEXT.md维护可接续状态，重要决策写docs/decisions，必要问题写development-issues。

已确认的设计不重复询问；常规实现取舍自主处理。发现必须改变产品权限、引入付费验证、扩大范围或破坏数据的选择时，先准备具体可审查方案再讨论。未满足任一验收项时保持目标未完成，不把已有部分功能重新定义成全部交付。
