## 一、目标、现状与实施边界

**目标项目：`D:\codes\KnowledgeOps Agent`。**

本计划整合此前审查意见和本轮确认的设计，完整替代聊天中的优化草案、局部补充与修订说明。后续执行者不应再自行拼接旧草案。现已整合到项目长期文档，供用户接下来设置的长期目标执行。

### 1. 优化后的产品目标

交付一个以聊天为主要交互、由Agent推进任务的Web应用：保留当前工具支持的通用任务执行能力，重点特化个人知识库业务。2026-10-10用户再次明确该定位，知识库不是唯一允许的任务类型。

- 普通问答、检索分析、工作文件处理和脚本任务可以独立交付，不强制创建知识草稿或写入知识库；学习引导和知识发布规则按相关任务适用。
- 用户决定学习方向、内容范围和最终取舍。
- Agent 默认了解本应用知识库的用途、组织方式、维护规则和内容质量要求。
- 面对新的宽泛知识任务，先梳理有依据、可修订的框架，明确必要的任务细节；后续通过交互灵活推进，不强制用户走固定课程。
- 用户可以随时追问、纠正方向、调整详略和要求整理。Agent 保存重要解释、例子、条件及未决问题，支持形成草稿、修订、确认保存和后续问答。
- 联网用于获取与核对知识，不默认把主题转换为无人参与的完整研究报告。
- 通用运行能力可靠，知识库业务能力有明确的规则、工具和验收，不能只依赖一段通用提示词。

更主动的引导应通过真实交互验证。不能稳定改善体验时，保留用户主导的可靠路径，明确报告增强能力的限制。

### 2. 保留与修复的基础

保留现有 LangChain `create_agent`／LangGraph、FastAPI、React、PostgreSQL、Celery＋Redis，以及本项目独立六服务容器组。

保留材料导入、网页读取、PDF/OCR、知识版本、事务发布、来源引用、有限研究子 Agent、运行记录、取消、手动恢复和备份恢复能力。此次是优化现有应用，不重新开发一套项目。

当前核查属于源码、文档和历史证据审查。旧版测试及评估报告不能直接证明优化版本通过；文档中的模型消费 **596 次**也是历史快照，实施前须读取实时账本。

### 3. 明确边界

- 不访问、导入、挂载或回写桌面个人知识库。
- 不使用共享开发容器；安装、运行、测试在本项目容器内。

## 二、完整设计与关键实现合同

### 1. 业务方法通过领域规则与 Skills 表达

保留强制加载的核心领域规则，说明知识库目的、内容组织、证据要求、维护原则及权限边界。核心规则缺失或不可读取时停止装配，不能静默退回无规则的通用 Agent。

新增项目维护的 Skills，至少覆盖：

- **交互学习与主题梳理**：明确目标、提供适量框架、纠正错误前提、适时建议下一步，允许跳转和回退。
- **知识整理与维护**：根据已经讨论的内容整理连贯正文，保留重要追问、解释和例子，判断补充、修订、新建及关联。
- **证据与内容检查**：检查来源、数值、单位、适用条件、否定关系和因果表述，区分格式正确与事实有据。

这些是方法指导，不是固定阶段路由。简单问题仍可由主 Agent 直接回答，不要求先计划、调用辅助模型或产生文档。

采用 Deep Agents 的渐进加载机制：默认提供技能目录，按任务读取正文和资源；核心知识库规则始终生效。

手工装配时使用 `SkillsMiddleware`，配合仅开放 `read_file` 的 `FilesystemMiddleware` 和只读技能快照 backend，不引入写文件、执行脚本等工具。[参考固定版本源码](https://github.com/langchain-ai/deepagents/blob/6a3a12bc5b3ac88aeb091e6c77ba81ad4d6732af/libs/deepagents/deepagents/middleware/skills.py)

技能源文件由项目代码仓库维护，不建设技能市场或 Agent 自修改机制。运行记录保存实际使用的名称、版本、内容哈希及对应正文、附件快照。

### 2. 保留主 Agent，新增一个通用模型调用工具

对外工具合同为：

```text
call_model(prompt, material_refs=[])
```

具体行为：

- `prompt` 由主 Agent 生成，包含任务、要求和必要的短文本。
- `material_refs` 可引用已存在的固定材料版本、知识版本、草稿修订或获准的运行产物及其范围，由程序读取原文后附加。
- 不接受任意本地路径，不根据引用参数自行联网获取材料。
- 使用同一 `deepseek-flash` 通道、统一网关和根任务预算。
- 使用独立输入，不自动继承主 Agent 全部历史，不注册业务工具，不创建另一个 Agent 循环。
- 返回完整结果状态、产物引用和必要预览；长结果持久保存后分页读取，不冒充主 Agent 最终答复直接展示。
- Skills 可以提供经过验证的任务方法或提示模板，但不把这个工具拆成固定的“写作模型”“审核模型”。

2026-10-09用户后续澄清：call_model在新任务中默认关闭，通过Web/API按任务显式启用，子Agent继承根选择；未启用时工具装配和服务入口均拒绝。启用后由主 Agent 判断是否需要调用。短回答直接完成；需要隔离上下文、集中处理材料或进行独立核对时，可以调用。辅助结果仍需主 Agent 结合任务判断，不能直接获得事实或写入授权。

用户随后进一步明确：既然关闭，就不再为该工具继续效果验收。本轮保留实现、默认关闭与已有离线控制测试，取消补完辅助模型对照和真实模型重验的交付要求，不为旧报告完成而临时启用。历史实验和失败原样保留，不改判为通过；依据[决策0019](decisions/0019-remove-auxiliary-experiment-gate.md)。

调用恢复使用 `run_id＋tool_call_id＋输入哈希` 关联实际模型预占与结果：

- 同一次调用成功后恢复，复用已有结果，不重复收费。
- 同一调用 ID 对应不同输入时拒绝复用。
- 不用提示词哈希对不同调用全局去重。
- 结果未知的请求保留已消费额度，不假装未执行或自动退款。
- SDK 隐式重试保持关闭；新的实际尝试分别预占、记录。

### 3. 上下文管理覆盖完整请求

替换当前仅按消息条数、字符数触发的主策略。容量检查必须包含：

> 系统规则＋已加载 Skills＋有效偏好＋运行控制信息＋消息历史＋工具结果＋工具 Schema＋输出预留。

主 Agent、子 Agent、辅助模型、摘要与意图解释均经过统一请求检查。

最终检查放在所有输入组装之后、供应商请求之前，避免中间件后续追加信息绕过限制。

按以下顺序处理容量：

1. 工具长结果先保存原文，只携带预览和补读引用。
2. 对可压缩的旧历史生成工作摘要，保留近期完整工具调用组。
3. 重新计算完整请求；仍然超限时减少可选资料或要求分段处理。
4. 单条用户输入、必需规则或工具 Schema 本身超限时明确反馈，不能截断成表面成功。
5. 摘要为空、截断、失败或预算不足时保留原始记录，不用损坏摘要替换历史。

借鉴 Deep Agents 的模型 profile、请求容量和完整消息组处理方式，摘要调用和原文存储仍接入本项目网关与产物服务。[参考上下文机制](https://docs.langchain.com/oss/python/deepagents/customization)

**实施前置验证：**

确认当前实际 `deepseek-flash` 渠道的输入限制、输出限制及可用计数方法，形成明确配置和测试。

不能将别名直接映射成某个公开模型的上下文容量，也不能照搬未知模型的默认窗口。无法取得可靠配置时，记录外部信息缺口，继续离线开发，但不宣称长上下文在线验收完成。

### 4. 区分运行恢复、跨轮延续和长期偏好

继续使用每个 run 独立的 LangGraph 检查点，不把整个会话强行合并成一个不断复用的执行实例。

新增不可变会话延续快照，记录：

- 产生快照的 run、代次和父快照；
- 已覆盖的用户消息序号；
- 工作摘要及近期完整消息组；
- 固定材料、草稿与产物引用清单；
- 格式版本与内容哈希。

新任务在首次领取时取得前序任务的最新有效快照，因此排队消息可以接上前一任务后来完成的结果。

继承背景、进展和引用，**不继承旧任务的授权、预算、待执行工具调用和执行位置**。

同会话任务按数据库序号执行，不依赖 Redis 到达顺序。较旧任务恢复后产生的结果可以保存和展示，但不得覆盖已经推进的较新会话快照。

跨 run 补读只允许冻结继承清单中的产物。旧来源需要用于新草稿时，从固定版本重新读取并登记当前任务证据，不放宽为任意跨任务读取。

### 5. 运行中引导与自然语言授权

**消息默认排队，用户点击“引导”后才投递给当前运行。**

引导消息与目标 root、代次和真实用户消息 ID 绑定。排队任务转为引导时，通过事务取消其独立执行资格，拒绝过期投递，确保不会执行两次。

引导接收后：

- 立即阻止旧决策继续产生新的业务写入。
- 正在进行的请求或已提交事务不能假装撤销。
- 在安全点保留已完成工具结果，明确标记未执行动作，再将引导送入模型。
- 通过检查点中的消息 ID、控制序号和数据库回执避免恢复时重复应用。
- 重新判断当前要求及授权，但不自动增加预算。

发布意图按真实用户消息版本更新，不能只保存第一次判断：

- 当前明确指令优先于 UI 默认选项。
- “保存刚刚这一版”须绑定同会话已展示的具体草稿修订。
- “不要保存”撤销本任务后续自动发布的许可。
- 条件句、引用文字、助手输出、摘要、Skills 和偏好不能成为授权来源。
- 模型解释语义，业务服务检查对象、版本、影响范围和幂等；UI 与聊天共用业务服务。
- 解释失败时不扩大授权，保留可完成的只读工作并明确反馈。

合并、拆分、批量归档等高影响操作仍须展示实际影响并取得相应确认。

### 6. 长期偏好：可以自动提取，但可查、可改、可撤回

PostgreSQL 保存偏好正文、适用范围、状态、来源消息、修订及取代关系。

- 明确表达长期适用的偏好可以生效。
- 推测得到、范围不明或存在未解决冲突的偏好进入待确认。
- “这次简短一点”等要求只影响当前任务。
- 不推断用户掌握程度，不自动生成学习进度。
- 当前任务明确要求优先于长期偏好；偏好不能改变权限、发布规则或预算。

新用户消息的偏好提取与发布意图解释合并为一次结构化调用，但两类结果分别校验、落库。按消息 ID 和解释器版本去重，不做后台历史全量扫描。

提供查看、编辑、确认、停用和删除界面。这些人工操作无需调用模型。

撤回后停止注入，并防止相同旧消息再次提取使其“复活”；历史记录仍可作为历史证据，不宣称已被物理擦除。

### 7. MCP：统一接入，默认不连接服务

采用当前官方 `langchain.mcp.MCPAdapter` 入口，依赖通过 `langchain[mcp]` 锁定。该入口目前标为 beta，以项目内薄适配层隔离变化；先验证协议和依赖兼容，不同时维护两套适配方案。[官方文档与版本要求](https://docs.langchain.com/oss/python/langchain/mcp)

交付以下能力：

- Web 管理连接、测试连接、发现工具、选择允许的工具、启停配置。
- 支持 stdio 和 Streamable HTTP。
- PostgreSQL 为唯一有效配置源；支持非秘密配置导入导出。
- 密钥使用环境变量引用，不回显或写入导出文件。
- 默认服务列表为空；临时本地 MCP 服务只用于开发验收。
- stdio 执行预先配置、已安装的入口，不自动安装程序，不通过字符串拼接任意 shell 命令。

**接口不按工具读写类型拆分。** 工具执行统一适配；许可策略单独处理：

- 新发现的工具默认未许可。
- 已审查无副作用的工具可允许自动调用。
- 可能产生外部修改、且没有相应具体授权的调用，展示服务、工具、参数和影响后等待确认。
- 配置启用不等于允许任意副作用；服务提供的 `readOnlyHint` 不能直接充当授权。
- 确认绑定连接版本、工具 Schema、参数和调用 ID；等待时释放 worker。
- 外部结果未知时不自动重试；成功回执可用于恢复复用。

MCP 调用纳入工具预算、超时、取消、长结果保存与审计。禁止 MCP sampling 等机制绕过统一模型网关。

外部返回内容是材料，不是指令；需要引用时保存来源快照和调用出处，不将服务回答自动视为已核实事实。

“仅知识库”模式不能通过 MCP 绕过外部资料限制。

### 8. 资源版本与恢复规则

根任务首次执行时冻结资源清单：核心规则、Skills、模型配置、MCP 连接及工具 Schema、所用偏好版本。子任务继承所需资源并缩小能力范围。

- 普通编辑默认从下一任务生效，当前任务保持版本一致。
- 禁用、撤回和删除在下一相关调用前重新检查，不能继续使用已撤销许可。
- 核心规则或必需资源失效时明确停止；可选工具失效时返回不可用，不悄悄切换其他服务。
- 恢复重建连接并校验兼容性，客户端对象和密钥不进入检查点。
- 历史运行缺少资源清单时标为旧格式，不补造当时配置。
- 旧检查点无法可靠兼容时保留历史成果，明确提示以新任务继续，不能猜测并重放副作用。

### 9. 修复知识业务与 Web 操作缺口

| 当前问题 | 确定的修复行为 |
|---|---|
| 更新正文时可能清空摘要、分类、标签、关系 | 更新合同区分“未提供”和“明确清空”；未提供时继承基础版本，明确清空才删除。 |
| 模型读取正文后拿不到维护所需完整信息 | 返回固定版本、正文、元数据和关系；修改前必须取得基础版本。 |
| 跨轮草稿只能看到编号或状态 | 补齐读取草稿、查看差异、修订、拒绝及确认指定修订的工具，与 UI 共用服务。 |
| 历史引用可能打开最新来源 | 所有引用导航保留证据 ID、来源版本和位置；页面与下载均能查看被引用版本。 |
| 草稿、任务列表截断导致旧数据不可见 | 服务端支持会话过滤和稳定分页，前端按需加载，不能先取全局前 100 条再本地过滤。 |
| 页面可能把子任务或排队任务当成当前执行任务 | 根任务、子任务、排队消息分别展示；当前活动区明确绑定正在运行的 root。 |
| 中文检索较宽泛、部分元数据未参与 | 调整现有词法检索的字段、权重和停用词，保留数字和技术词；用固定查询验证，不扩展为向量检索。 |
| 工具事件可能保存完整长结果或敏感参数 | 先存完整产物，事件只保存有界预览和引用；统一应用密钥脱敏与敏感字段处理。 |

来源格式、草稿正文、发布正文和最终回复分别检查。可点击链接只能证明链接可解析，不能替代事实与表述审读。

保留本机单用户定位，同时补足 Host／Origin 校验，防止网页来源绕过本地管理入口；不扩展成公网认证系统。

### 10. DeepSeek 协议适配
