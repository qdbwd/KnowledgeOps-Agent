# 0011：冻结运行资源与跨轮延续的实现边界

- 日期：2026-10-09。
- 状态：现行完整优化计划的实施取舍；局部离线验证已取得，整个优化版仍未完成。
- 对应计划：步骤3、5、6、7，不改变产品范围、权限或费用。

## 复用与项目职责

Skills复用Deep Agents 0.7.23的SkillsMiddleware与仅read_file的FilesystemMiddleware。
源码基准为[6a3a12b的skills.py](https://github.com/langchain-ai/deepagents/blob/6a3a12bc5b3ac88aeb091e6c77ba81ad4d6732af/libs/deepagents/deepagents/middleware/skills.py)。上游解决发现和渐进读取；本项目负责只读backend、不可变快照、实际读取回执、撤回与业务权限，不暴露任意宿主文件或脚本执行。

DeepSeek复用[DeerFlow固定提交的协议恢复实现](https://github.com/bytedance/deer-flow/blob/7797409355cbf257923a81ab9781b706c38f9c3c/backend/packages/harness/deerflow/models/patched_deepseek.py)中的小型helper，保留许可证和出处。本项目逐请求disabled优先，真实reasoning_content与工具消息关联保留；不声称空协议字段恢复了推理内容。

LangGraph每run独立检查点保存执行状态。会话延续是本应用的业务合同：新任务继承资料、摘要和完整历史组，重新拥有自己的权限、预算和执行位置。没有把同一会话的所有消息塞进同一个执行线程，也没有让框架猜测应用的授权规则。

## 冻结什么、何时冻结

首次执行在意图解释等任何收费调用之前冻结核心规则、技能文本与附件、关键提示词、模型容量和非秘密配置。子任务继承同一root清单。普通代码资源编辑从下一任务生效，缺失核心规则、撤回或模型通道不兼容有明确错误；连接对象及密钥不进入清单。

主Agent自行调用通用call_model时给prompt与固定材料引用；程序读取原文，统一网关预占，响应和输入保存为独立产物。它不继承主对话、没有业务工具、不形成新Agent循环。真实输入哈希与run/tool_call_id绑定；同调用成功后恢复复用，不把相同提示词用于不同任务的请求全局去重。

辅助调用在本轮默认逐请求关闭thinking，使所分配的输出预算用于具体结果；主Agent思考设置不受影响。效果需要正式配对实验决定，不预设收益。

## 数据库序号与延续快照

用户消息入队时在会话行锁下分配序号。broker只负责通知，领取时拒绝跳过同会话的较早排队任务。

父快照在首次领取时绑定，因此后续排队任务能看见前一任务后来产生的结果。恢复继续使用原父快照；终态和新快照在同事务保存。较旧任务后来恢复只产生自己的历史分支，不覆盖较新任务推进的会话指针。

跨run读取产物只接受父快照冻结的ID清单。后续新增的旧run产物不会自动变成已继承资料。旧材料用于新正文时仍须登记本任务证据，不把继承清单当成来源验证或发布许可。

## 验证与限制

资源、技能实际读取、通用模型隔离及回放、队列乱序、快照单调推进、跨run产物范围均有针对性测试，具体批次见progress和development-issues。正式库目前0011；资源/延续/引导迁移均先在隔离schema验证后再应用。

引导复用LangChain 1.4.3的before_model/after_model/after_agent钩子与hook_config路由，不改框架源码。上游factory.py负责跳回模型循环，本应用负责真实消息、精确代次、授权epoch和事务屏障。模型请求中收到引导时，尚未执行的提议生成明确未执行的ToolMessage，保留完成结果和协议配对。即使DB已应用引导但checkpoint落后，旧决策epoch也不能借新许可执行写入。

以上不是在线模型效果、浏览器完整体验、MCP业务许可、长期偏好或引导安全点的完成证明。当前实现按现行计划继续补齐这些能力，旧24/36报告不替代优化版验收。
