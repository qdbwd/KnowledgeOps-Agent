# 0022 本地文件工作区与正文文件存储

2026-10-10。依据用户明确要求：采用本地执行方式，给 worker 挂载专用 Windows 文件夹，补齐读写工具，将知识正文、上传材料和文件产物放入工作目录；具体数据库范围由开发者设计。取代旧范围中“不做通用脚本能力”和“知识正文只存 PG”的约束，不改变项目与个人知识库隔离。

## 采用方案

直接依赖锁定的 Deep Agents 0.7.23 `FilesystemMiddleware`、`LocalShellBackend`，提供 ls/read_file/glob/grep/write_file/edit_file/delete/execute。沿用真实 SDK 的 Schema、分页、编辑前读取与错误协议。对照 DeerFlow 最新核对提交 `ab9920f25f1560a38a7820a52469ef3dc5767071` 的 LocalSandboxProvider、local_sandbox、路径挂载与超时测试，采用工作/上传/输出的职责划分；没有复制 DeerFlow 沙盒服务或创建 AIO 容器。

薄适配负责冻结 Skills 的只读路由、管理目录保护、执行时限与干净环境，并接入现有工具策略、根任务预算和撤回。新工具仅供主 Agent；既有子 Agent 的只读能力不扩大。`read_file` 的稳定 ID 保留，新根任务明确绑定工作区；旧快照不因升级而扩大文件读取范围。初始化只开放从未配置的新项，不复活用户已经关闭的工具。

用户进一步明确：需要像与 Codex 聊天一样自由修改正式知识文档，通用工具应构成可组合的基础能力，而不是每种文字操作都只能通过业务专用接口。本项目据此将 `knowledge/documents` 作为可编辑知识工作树，文件工具直接作用于这里；写入、编辑、删除和脚本执行后，由 KnowledgeFileSyncMiddleware 自动发现改动并接入原知识服务。Skills 保存操作经验与质量要求，专用工具处理适合独立封装的业务动作，MCP/子 Agent 是按需扩展方式，不要求基础工具为每个任务预先写好固定流程。

默认宿主路径 `data/agent-workspace`，容器路径 `/data/agent-workspace`。dev、API、worker 挂载同一目录：worker 执行、API 上传/编辑/下载、dev 迁移维护都需要访问；不只挂 worker 导致其他入口读不到文件。可用 `AGENT_WORKSPACE_HOST` 更换专用宿主路径。

## 数据职责与一致性

- 文件：可编辑知识工作树、上传原件/网页快照、不可变知识正文版本、长运行产物、工作与交付文件。
- PG：文档 ID、版本号、标题/标签、路径/哈希、引用/关系、草稿修订、聊天、运行、事件、检查点、延续摘要、任务笔记、偏好与配置。
- 派生文本：PG 保留解析片段、引用摘录和 BM25 索引。这些是读取和追溯需要的数据，不另立第二份可编辑的正文事实来源。
- `knowledge/current` 是通过既有 Markdown 导出器生成的阅读视图；正式来源是 PG 版本指针与 `knowledge/versions` 的不可变正文。文件名采用稳定 ID，标题/标签/关系在 manifest 中。

直接保存模式下，通用写工具自动建立草稿并提交新版本；预览模式下保留工作文件和待确认草稿，连续编辑修订同一草稿，不为同一文件不断创建新文章。草稿记录工作文件路径和内容指纹，用户批准后仍输出到原文件。既有引用、基础版本、取消/撤回及合并拆分确认规则继续生效。校验失败保留工作文件并明确 `sync_failed`；外部编辑、崩溃中断或补充修正后可显式调用 `sync_knowledge_files`，不依靠模型每次记住普通编辑后的维护步骤。

先写不可变文件，再提交 PG 引用和索引。事务失败可能留下未引用文件，不会提交尚未写好的正文；当前不自动清理孤立文件。文件缺失或哈希不符明确失败，不能回退到旧 PG 正文。已有内联正文迁移后清空，保留旧列用于兼容未迁移数据；迁移可重入且不删除旧原件卷。

当前阅读目录在发布后刷新、启动时修复；刷新失败返回“正文已发布、文件视图待同步”，不让客户端误以为发布失败。单个文件原子替换、manifest 最后更新，但跨文件不宣称原子事务；完整 ZIP 导出仍在一致快照中生成。工作文件刷新会比较内容指纹，旧发布回执不能覆盖后来尚未同步的编辑；不参与应用锁的外部编辑器仍不得与发布并发改同一文件。人工修改 current 不自动入库，修改不可变正文会报完整性错误。

同步有明确规模边界：工作树最多1000个Markdown、单文件800KB、合计20MB，一次变更最多20篇，正式正文还受现有20万字符上限约束。删除工作文件表示归档；原生改名目前表现为归档旧文章并新建，不保证原文章ID。跨多个既有待确认草稿的批量改动需要分别同步。通用文件/命令工具并未因此变成任意规模的文件同步系统。

## 边界与验证

本地执行不是操作系统级沙盒。文件工具的虚拟根与符号链接检查不能限制 shell；命令拥有 worker 的进程权限，清理环境变量也不是凭据安全隔离。仅承接本机可信个人任务。脚本不自动幂等；恢复可能重放尚未形成工具回执的命令，写脚本应自行处理重复执行。默认命令时限60秒，设置上限300秒。最初GNU timeout的包装已由下述运行中控制取代，脱离进程组的后台任务仍不在强隔离保证内。

备份升级为 PG、费用库、完整 workspace 同一组；备份前停应用写入和本地编辑。保留旧格式原件卷备份的读取能力。验证采用隔离 PG 与文件夹、真实 SDK/Agent 图和离线供应商响应，覆盖迁移非空数据、引用/索引/导出、文件边界、脚本时限、工具撤回和下载；不以此声明模型一定选择正确工具。实际结果写入 progress。

## 后续落实：worker本地执行生命周期

用户明确开始本地沙盒接入后，复核上游DeerFlow `f71999d9`、Deep Agents `9f0e39d5`。SDK工具与文件合同继续直接复用；有界捕获摘取DeerFlow，Linux进程执行按项目JobService控制适配。取消、租约和活跃时间预算每秒检查；超时/中断清理普通进程组，正常完成也不保留同组后台服务，避免工具结束和知识同步以后脚本继续写文件。该行为差别已加入模型可见说明。

不新增AIO服务、会话容器、重复配置入口或数据库表。共享工作区和每次新shell的约定不变，`.env`现有命令时限继续有效，工具管理仍使用`middleware:execute`；旧任务不会因升级获得新工具权限。仅保留64,000原始输出字节并持续排空管道，大日志应显式写文件补读。结果继续使用SDK退出码/截断字段和应用事件记录，不增加面向用户的开发报告页面。具体运行顺序、限制、来源及验证入口见architecture/progress。
