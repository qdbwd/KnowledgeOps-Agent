# 0002：项目拥有独立知识库

- 状态：所有权与隔离继续有效；应用与发布方式由 [0006](0006-v1-web-application.md) 更新，当前文件存储按 [0022](0022-local-workspace-and-file-storage.md) 执行。
- 日期：2026-09-22

## 背景

早期任务方案把桌面个人知识库描述成 Agent 的首个真实语料场，容易把“个人知识库项目”和“Agent 实战项目”混为一体，也会让项目文档、代码和数据边界互相污染。

## 决策

KnowledgeOps Agent 管理项目自己的知识库，并拥有相关读取、检索、写入、更新、删除、索引和审计能力。初始预留的 `data/knowledge_base/` 已弃用并清理；当前可编辑知识正文位于 `data/agent-workspace/knowledge/documents/`，历史版本保存在同一工作区的 `knowledge/versions/`，PG保存元数据、引用、运行和派生索引。实际写入及审批规则按现行产品设计执行，不再使用旧目录作为实现入口。

`C:\Users\cyq\Desktop\个人知识库` 保持独立，不作为本项目默认运行时数据。本项目不自动读取、复制、索引、修改或回写个人知识库；其中的知识库设计和任务文档仅作为参考。

## 后果

- Agent Demo 可以真实展示知识库问答和知识维护闭环；
- 项目测试可以使用自己的 Markdown 夹具，不受个人知识库变动影响；
- 项目知识库的版本、审计、回滚和评估由本项目负责；
- 将来如需跨库接入，必须另设显式只读/写入适配器和授权，不得隐式同步；
- 旧任务方案不再是本项目的实施入口，项目内 `PROJECT_CONTEXT.md` 和 `docs/implementation-plan.md` 为当前工程上下文。
