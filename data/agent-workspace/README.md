# Agent 文件工作区

默认对应 Windows 的 `D:\codes\KnowledgeOps Agent\data\agent-workspace`，容器内为 `/data/agent-workspace`。在 `.env` 中设置 `AGENT_WORKSPACE_HOST` 可以换成另一个专用文件夹；更换前应停应用并搬齐文件，不能只改路径后继续读取旧数据库。

| 目录 | 内容与维护方式 |
|---|---|
| `work/` | 你放入的材料、临时脚本和处理中间文件。Agent 可读写。 |
| `outputs/` | 普通交付文件。Agent 可读写，通过 `present_files` 返回下载链接。 |
| `uploads/originals/` | 上传、导入、网页获取的原件，按内容哈希保存。来源名称和版本映射在 PG。 |
| `knowledge/documents/` | 可以编辑的正式知识工作文件，支持子目录。通用文件工具或命令修改后自动尝试同步到发布版本和索引。 |
| `knowledge/versions/` | 发布后的不可变 Markdown 正文，文件名是版本 ID。由知识业务服务写入。 |
| `knowledge/current/` | 当前知识的可重建阅读视图，包含正文、相对引用及 `manifest.json`。 |
| `artifacts/` | 长工具结果、压缩前上下文等运行文件；任务和内容哈希决定路径。 |
| `.home/` | 命令执行的专用 HOME，不继承宿主用户主目录。 |

直接放入 `work/` 不会自动变成已引用来源；让 Agent 使用 `import_file` 登记，再读取来源。可以直接让 Agent 修改 `knowledge/documents` 中的知识正文，无需指定业务工具。用户要求预览时保留工作文件和同一草稿的连续修订，正式版本/索引待确认；校验失败同样保留文件并返回失败原因。用 Windows 编辑器修改后，需要让 Agent 使用 `sync_knowledge_files` 指定同步文件，不会后台自动发布。每次同步最多20个文件。

`knowledge/versions` 是不可变的历史正文，手改会触发完整性错误；`current` 是带相对引用的阅读导出，会在下次导出时覆盖。两者都不是编辑入口。工作文件删除表示归档，历史版本仍可追溯；直接改名目前按归档旧文章和新建文章处理，不能保留原文章 ID。不要在应用发布的同时用外部编辑器写同一个文件。

命令由worker进程在其所在容器内执行：开发模式是dev容器，生产部署模式是独立worker容器。两种模式都把同一宿主工作区挂载为`/data/agent-workspace`，使用Linux命令、Python和已安装依赖。本地执行后端直接启动子进程，没有需要连接的独立沙盒服务。这里没有额外AIO容器或chroot；文件工具限制虚拟根，命令仍拥有worker进程的文件系统权限。仅用于本机可信任务，不运行不可信任意脚本。

命令默认最多60秒，可在`.env`用`WORKSPACE_EXECUTE_TIMEOUT`配置（1至300秒）。运行中检查任务取消、租约和活跃时间预算；工具完成、超时或取消时清理普通子进程，文件不会自动删除。不通过`&`启动需要长期存活的后台服务，需要脚本内部并行则以前台`wait`等待完成。每次都是新shell，不继承上次的cd/export，也没有交互输入。

stdout/stderr合并，最多保留64,000原始字节，超过会明确报告截断。完整日志应在命令中写入`work/任务.log`，之后用`read_file`分页读；截断后的工具回执不能代替完整日志。

文件内容均被 Git 忽略。迁移/换设备时必须同时备份数据库和这个工作区；旧 `source-data` 卷只作迁移保留，不再保存新原件。个人知识库不是这个目录。
